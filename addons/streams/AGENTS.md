# streams — инструкции для агентов

Модуль переработки системы сообщений Odoo 15 (потоки, каналы записей,
уведомления, гостевой доступ). Общие правила репозитория — в корневом
`AGENTS.md`; здесь только специфика модуля.

## docs/roadmap.md — главный документ проекта

`docs/roadmap.md` — живая версия ТЗ. Правила работы с ним:

- Перед любой задачей по модулю прочитай его целиком: терминология (§2),
  архитектура (§3) и правила потоков (§6–§8) обязательны к соблюдению.
- Реализовал часть ТЗ — перенеси/опиши её в разделе **«Сделано»** (с номером
  фазы и датой). Отступил от ТЗ — зафиксируй отступление там же.
- Отложенные проверки и хвосты — в раздел **«To check / to do»** (чек-боксы);
  выполнил проверку — отметь и опиши результат.
- Изменение самого ТЗ (по решению пользователя) вносится прямо в текст
  соответствующего параграфа, с пометкой.

## Дизайн-документы фаз

`docs/design-phase1.md`, `docs/design-phase1b.md`, `docs/design-phase2.md`,
... — контракты исполнителей конкретных фаз: карта фактов ядра с file:line,
состав работ, обязательные тесты. Исторические документы: после завершения
фазы не редактируются (актуальное состояние — в `docs/roadmap.md`). Дизайн
новой фазы кладётся туда же: `docs/design-phase<N>.md`.

Вся проектная документация модуля живёт в `docs/`; в корне модуля файлов
документации не заводить (кроме этого AGENTS.md и CLAUDE.md).

## Ключевые инварианты модуля

- Чаттер записи и канал записи — две проекции одного набора `mail.message`
  (m2m `stream_channel_ids`), не два хранилища.
- Подписка (followers) только явная; followers — только внутренние
  пользователи; участники канала ⇄ followers синхронизированы двусторонне
  (guard-контекст `streams_sync`).
- Внутренние пользователи не получают email из записей. Никогда.
- `change`-сообщения не влияют на unread и сортировку каналов.
- Bus-рассылка проекций — только участникам с правом чтения записи-источника.

## Тесты

Все сценарии — в `tests/`. Любая правка модуля прогоняется
`run_odoo_tests(modules="streams")`; ломать существующие сценарии нельзя без
явного решения архитектора, зафиксированного в roadmap.
